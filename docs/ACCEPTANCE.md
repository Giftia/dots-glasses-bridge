## 新安装验收

1. **本地代码与服务。** 执行 `npm ci`、`npm test`、`npm run check`；启动后确认本地监听及外部 HTTPS `/dots/health` 正常。健康响应只证明服务入口，不证明 Dot 已连接。
2. **原 Dot 与事件。** 完成 OAuth，确认所需工具与订阅可用；发一条不含隐私的消息，分别观察保存、事件接受、原 Dot 读取和真实回复。状态、事件投递和回传需要对应同一轮。
3. **眼镜文字与上下文。** 在真眼镜提出一个问题，查询回复，再追问原因、回答一个明确选项、要求重新开始；确认普通追问接续原对话，重开后不误用上一轮答案，播报只给短摘要。
4. **眼镜照片与图文。** 拍摄无敏感信息的物体，确认 Dot 依据真实照片回答；追问上一张，再添加新照片。让 Dot 回传一张图和一个文件，在手机打开有效链接并核对内容；链接过期后应拒绝访问，附件过期不能伪称仍可查看。
5. **可选微信。** 使用专属账号绑定与单一 worker，测试本人文字、真实照片、完整回复、附件入口和已授权主动通知。须在手机实际确认显示；遇到 `rejected`、`unknown` 或 `outbound_blocked` 即记录未通过，不以 HTTP 200 或桥接保存成功代替。

微信长回复拆分、进程中断后的恢复和拒绝状态保护有代码测试；如果你的验收目标含长文或后台稳定运行，应另外进行受控实机测试。没有当次物理证据时，不把历史照片或报告成功扩大为多段长文送达通过。

验收记录建议只保留版本、环境类别、检查时间、状态和脱敏结论，不公开聊天正文、照片、账号标识、凭据、完整查询参数或签名结果链接。排查见 [TROUBLESHOOTING](TROUBLESHOOTING.md)。
