# 发布检查记录

首次干净 Linux 检查发现旧测试引用本机公开二进制缓存，候选未公开即停止发布。测试已改为从官方固定版本下载并校验 SHA-256，缓存不执行、不提交仓库，不再依赖维护者工作区。下载仅用于公开测试夹具，不访问微信或真实代理。

本记录针对 2026-10-26 的首个通用源码候选，不替代部署者自己的平台授权、眼镜和微信实收验收。

| 检查 | 结果与范围 |
| --- | --- |
| Windows 本机完整回归 | Node 24.21.0：263 项，262 通过、0 失败、1 跳过；跳过项需要 Windows 文件符号链接权限 |
| 旧运行时兼容子进程 | 同一完整回归中，以显式 DOTS_COMPAT_NODE 指向 Node 16.14.2，运行媒体、微信解析及持久化子进程检查；开发测试运行器仍为 Node 24 |
| 语法 | 所有源码、工具和测试的 JavaScript 语法检查通过 |
| 受限恢复 | 8 项测试包含明确拒绝与 unknown 的区别、先备份、单次新发送、旧回执保留，以及 CLI 的真实临时文件编排；微信网络均为注入模拟 |
| 依赖 | 官方 npm registry 的 production audit 为 0 vulnerabilities；这不等于不存在未公开问题 |
| 发布脱敏 | 自动模式扫描、私有部署标记/已知凭据对照、独立只读审查均未发现应公开的真实凭据或私人部署资料；8 个合成网址测试文件按完整 SHA-256 审查列入允许表 |
| 文档 | 相对链接、两个 MCP 入口、配置参数与状态含义经过核对 |
| Linux 和干净克隆 | 由仓库 Checks 工作流单独记录，不以本机 Windows 结果代替 |

运行检查：

    npm ci --ignore-scripts
    npm run check
    npm test
    npm run audit:release
    npm audit --omit=dev --registry=https://registry.npmjs.org

使用其他兼容运行时只需显式设置 DOTS_COMPAT_NODE；默认子进程复用当前 Node。不要把私有可执行文件路径写进测试源码。

当前代码仍为单实例、容量有限的个人自托管桥。媒体过期不会自动删除原文件，消息历史不自动归档；到达硬上限会拒绝新输入。原生 Events 和账号权限需要实际确认。历史照片与报告往返成功不证明某次新的微信拒绝已经恢复；维护实例最近的微信恢复仍待服务器执行及手机确认。
